# OTA 下载可靠性规范（永久强制）

> **状态：永久生效。** 任何涉及下载器（`UpdateInstaller.kt`）、镜像源、Release 发布流程的改动，交付前必须逐条对照本文档复核。本文记录的是反复发生、每次都导致车机用户无法更新的真实事故，教训必须永久遵守，**不允许再出现相同错误**。

## 一、事故档案

### 事故 #4（2026-11-19，v3.5.4 修复）：镜像静默返回 HTML 错误页，sha256 必败

- **现象**：v3.5.2 车机 OTA 更新 v3.5.3，报「安装包校验失败（sha256 不匹配），已清理重试」，重试无效。且安装包仅 3.4MB，与「大文件断流」无关。
- **实测证据**（当日沙箱 curl 实测，正确应为 3435585 字节 / sha256 `2a4d8d35…` / ZIP 头 `504B0304`）：

  | 下载源 | 实际返回 | 后果 |
  |---|---|---|
  | ghproxy.link（镜像池内） | 1739 字节 **HTML 错误页**（头 `3C21444F`=`<!DOCTYPE`） | 长度检查通过 → sha256 必败 |
  | gh-proxy.net（镜像池内） | 195 字节 **HTML 错误页** | 同上 |
  | ghfast.top | ✅ 正确内容 | 可用 |
  | gh-proxy.com | ✅ 正确内容 | 可用 |
  | github.moeyy.xyz | 连接超时（该网络环境下不可达） | 不可用 |
  | 直连 github.com | HttpURLConnection **不跟随跨主机 302**（github.com → objects.githubusercontent.com），`instanceFollowRedirects=true` 下直接把 302 返回给调用者 | **直连通道自 v3.1 起从未真正工作过** |

- **完整因果链**：两个镜像全部静默失效（返回自带 Content-Length 的 HTML 错误页）→ 长度完整性检查形同虚设 → sha256 必败；直连通道因跨主机重定向不被跟随而形同虚设 → 四条路全堵死 → 用户侧只看到无诊断价值的「sha256 不匹配」。
- **教训**：
  1. **长度检查 ≠ 内容正确**——错误页/篡改内容可以带正确的 Content-Length；
  2. **镜像会静默失效**——不实测就永远不知道它返回的是 HTML 还是文件；
  3. **无诊断信息的报错会浪费每一次排查**——「sha256 不匹配」六个字让三次事故都从零开始查。

### 历史事故时间线

| 版本 | 事故 | 根因 |
|---|---|---|
| v3.1 → v3.4 期间 | 车机 OTA 反复「sha256 不匹配」 | `.part` 半截文件被跨镜像复用续传拼接，不同源内容错位（v3.4.1 修复） |
| v3.2 老客户端 | 46MB 大包下载必败 | 大文件断流概率高（v3.5.2 R8 瘦身 49MB→3.3MB 缓解） |
| v3.5.2 → v3.5.3 | OTA「sha256 不匹配」 | 镜像静默返回 HTML 错误页 + 直连通道虚设（v3.5.4 修复，即本文事故 #4） |

## 二、硬性规范（永远不许再犯）

1. **下载内容必须做魔数校验**：APK = ZIP（头 `50 4B 03 04`）。下载完成后必须先验文件头再验 sha256。只查长度的完整性检查一律视为不完整——错误页和篡改内容都能带正确的 Content-Length。
2. **镜像池只放实测可用的源**：新增/更换任何镜像前，必须用 curl 实测下载真实 release 资产并比对 sha256，禁止「看起来可以用」就直接进镜像池。镜像有寿命，**排查一切下载问题的第一步永远是重测镜像池**（命令见第三节）。
3. **跨主机重定向必须手动跟随**：`HttpURLConnection` 的自动重定向只跟随同主机同协议，GitHub release 下载的 302（github.com → objects.githubusercontent.com）会被静默返回。凡直连 GitHub 下载必须手动逐跳跟随（`openFollowRedirects`）。
4. **失败必须携带诊断证据**：错误消息必须包含实际字节数 / 文件头 hex / 实际 sha256 前 8 位等可定位信息；多源回退失败时必须汇总每个源的失败原因。**禁止静默吞掉异常后只给「校验失败」这类无证据文案。**
5. **`.part` 半截文件必须与下载 URL 绑定**：按 URL 哈希命名，禁止跨源复用（事故：v3.4.1 修复的拼接错位）。
6. **发布前服务端复核**：release 资产必须 state=uploaded、本地 sha256sum == GitHub API digest；发布后立即用至少一个镜像源实测下载新版本资产并校验（模拟用户真实下载路径）。
7. **修改下载器必须做异常源回归**：本地模拟三类异常——HTML 错误页响应（验证魔数拦截）、截断响应（验证长度检查）、长度相符但内容错误（验证 sha256 拦截），三类都必须被拦截且报错包含诊断信息。
8. **禁止在未确诊根因前发布「尝试修复」版本**：先实测确诊（第三节清单），再改代码，避免用用户设备当试验田。

## 三、排查清单（遇到「sha256 不匹配」先做这个，10 分钟定位）

```bash
# 1. 确认服务端资产正确：本地构建 sha256 与 GitHub API digest 一致
sha256sum app-release.apk
gh api repos/<owner>/<repo>/releases/latest --jq '.assets[] | {name, state, digest}'

# 2. 逐个实测镜像池（替换 URL），任何源返回非 ZIP 头（504b0304）即失效
for m in "" "https://ghfast.top/" "https://gh-proxy.com/"; do
  curl -sL --max-time 60 -o /tmp/t.apk "${m}https://github.com/<owner>/<repo>/releases/download/<tag>/<file>"
  echo "$m size:$(stat -c%s /tmp/t.apk) head:$(head -c4 /tmp/t.apk | od -An -tx1 | tr -d ' \n') sha:$(sha256sum /tmp/t.apk | cut -c1-8)"
done

# 3. 对照失败报错里的诊断信息（实际大小/文件头/实际哈希）与第 2 步结果定源
```

判定规则：`head` 非 `504b0304` → 该源失效（返回错误页/重定向页），从镜像池移除；`size` 不符 → 截断/篡改；两者都对但 `sha` 不符 → 内容被替换（高级威胁，核实 GitHub 侧 digest 与本地构建）。
